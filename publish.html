Step 3

人が確認し、GitHub Pagesで公開する

Codexの変更をそのまま公開せず、事実、権利、表示、Push先を人が確認します。GitHub Pagesの設定後、公開URLでもう一度確認して完了です。

このページの完了条件

  • 掲載内容、連絡先、画像の権利、未公開情報を確認した
  • PCとスマートフォンで表示、リンク、画像を確認した
  • Push先の自分用リポジトリとbranchを確認した
  • GitHub Pagesの公開URLを開いた
  • 公開URLで内容と表示を再確認した

このページで行うこと

  • 内容と権利
  • 表示確認
  • Push先
  • GitHub Pages
  • 公開URL

掲載内容と権利を人が確認する

AIや自動テストでは判断できない項目を、研究代表者または公開責任者が確認します。

  • 研究内容が正確で、公開してよい表現になっている
  • 氏名、所属、肩書が最新である
  • 論文・業績の著者名、題名、年、リンクが正しい
  • 問い合わせ先が正しく、公開してよい
  • 写真・ロゴの掲載権利と必要な同意を確認した
  • 未公開の研究情報、個人情報、認証情報が混入していない
  • テンプレートのライセンスと帰属表示を維持している

判断をAIへ任せない

事実関係、掲載許可、画像の権利、未公開情報の有無は、人が原資料と関係者への確認に基づいて判断してください。

PCとスマートフォンの表示を確認する

  1. ローカル表示をPC相当の幅で開き、メニュー、見出し、文章、リンク、画像、Contactを確認します。

  2. スマートフォン相当の幅でも開き、横スクロール、文字のはみ出し、メニュー操作、画像の切れがないか確認します。

  3. 内部リンクと外部リンクを開き、意図したページへ移動することを確認します。

  4. 画像が表示され、内容に合う代替テキストが設定されていることを確認します。

成功状態

PCとスマートフォンの両方で、主要情報へ到達でき、誤った文章・リンク・画像がない状態です。

Push先を確認する

  1. GitHub Desktopで、左上のCurrent repositoryが自分用リポジトリであることを確認します。

  2. Current branchが、公開に使う予定のbranchであることを確認します。分からない場合は推測せず、リポジトリ管理者へ確認します。

  3. 変更一覧とcommit内容を確認し、公開不要なローカル入力ファイルや認証情報が含まれていないことを確認します。

  4. Codexがまだcommit・pushしていない場合は、確認済みの変更だけをcommit・pushするようCodexへ依頼します。

  5. GitHub上の自分用リポジトリを開き、変更が反映されていることを確認します。

GitHub Pagesを設定する

GitHubの画面表示は変更される場合があります。項目名が異なる場合は、GitHub公式のPages文書を確認してください。

  1. GitHub上の自分用リポジトリでSettingsを開き、左側のPagesを選びます。

  2. Build and deploymentで、テンプレート本体の案内に従って公開元を選びます。標準構成ではDeploy from a branchを使います。

  3. 公開するbranchと/(root)を選び、保存します。

  4. GitHubが表示する公開URLを確認します。反映まで時間がかかる場合は、表示される案内に従って待ちます。

GitHub公式：公開元を設定する

公開URLでもう一度確認する

  1. GitHub Pagesに表示された公開URLを新しいタブで開きます。

  2. トップページ、ナビゲーション、研究内容、人物情報、論文・業績、Contact、画像、外部リンクを確認します。

  3. PCとスマートフォンの両方で確認します。ローカルでは表示できても、ファイル名の大文字・小文字やパスの違いで公開環境だけ画像が欠ける場合があります。

  4. 問題がなければ公開完了です。問題があれば「どの画面で／何を押したら／何と表示されたか」をCodexへ伝え、修正後にもう一度公開URLを確認します。

設定保存だけでは完了ではありません

このマニュアルでは、公開URLで正しい内容と表示を確認した時点を公開完了とします。
