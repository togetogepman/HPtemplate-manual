GitHub Pagesで公開・更新する

Codexの変更がGitHubへPushされていることを確認し、GitHub Pagesで研究室サイトを公開します。

このページで行うこと

  • GitHubへの反映を確認する
  • GitHub Pagesで公開する
  • 公開後に更新する

GitHubへの反映を確認する

Codexが今回の変更をCommitし、作業branchをGitHubへPushしたことを確認します。

Commit（コミット）
選んだ変更内容を、一つの記録としてパソコン上に保存することです。
Push（プッシュ）
パソコン上のCommitをGitHubへ送ることです。

  1. Codexの最終報告で、commit hashとpush先が自分のリポジトリと作業branchに対応していることを確認します。

  2. 必要な場合はGitHub DesktopでHistoryを開き、今回のCommitを確認します。未コミット変更が残っていないかはChangesで確認できます。

  3. CommitだけでPushされていない場合は、GitHub上のリポジトリへ変更が反映されていません。

CodexがCommit・Pushしていない場合

利用者が手動操作する必要がある場合だけ、次の最小手順を行います。

  1. GitHub DesktopのChangesで変更ファイルを確認し、Summaryへ短い説明を入力します。

  2. Commit to mainを押します。別のbranchを選んでいる場合は、そのbranch名がボタンに表示されます。

  3. Commit後にPush originを押し、変更をGitHubへ送ります。

GitHub Pagesで公開する

GitHub上の自分のリポジトリを、ホームページとして公開します。

  1. ブラウザで、テンプレートから作成した自分のリポジトリを開きます。

  2. リポジトリのSettingsを開きます。見当たらない場合は、リポジトリ上部の追加メニューも確認します。

  3. Settings内のPagesを開きます。

  4. Build and deploymentのSourceで、Deploy from a branchを選びます。

  5. 公開元のbranchにmain、フォルダに/(root)を選び、Saveを押します。

  6. 設定を保存します。

  7. 公開処理が完了するまで待ちます。初回は表示まで数分かかる場合があります。

  8. Pagesに表示された公開URLを開き、文字や画像が正しく表示されるか確認します。

公開範囲を確認

GitHub Pagesのサイトはインターネット上から見えます。意図しない文章、画像、個人情報が含まれていないか確認してください。

公開後に更新する

ここからは初回公開後の日常更新です。最初に作った同じローカルリポジトリを使います。

  1. 同じローカルリポジトリをCodexで開きます。

  2. 変更したい内容を具体的に依頼します。詳しい依頼方法はCodexで編集するを参照してください。

  3. 変更後の表示と、氏名や研究内容などの事実を確認します。

  4. Commit・Pushの完了と、push先を確認します。

  5. 公開ページを再読み込みし、更新が反映されたことを確認します。

更新のたびにリポジトリを作り直さない

テンプレートから新しいリポジトリを作る操作は初回だけです。以後は、同じリポジトリ内のファイルを更新します。

このページの完了条件

公開URLで研究室サイトを表示し、内容が正しいことを確認できれば公開完了です。
