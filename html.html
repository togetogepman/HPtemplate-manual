ChatGPT & Codex Guide

ChatGPTとCodexでサイトを編集する

ChatGPTで掲載内容を整理し、Codexへリポジトリの変更、表示確認、テスト、Commit、Pushまで依頼する基本手順を案内します。

ChatGPTとCodexの役割

ChatGPTは研究室情報や依頼内容の整理に使い、CodexはローカルリポジトリのHTML、CSS、画像などを変更するために使います。AIの作業結果はそのまま公開せず、最後に人が事実と表示を確認します。

このページの内容

  1. ChatGPTアプリを準備する
  2. 研究室の情報を整理する
  3. Codexでリポジトリを開く
  4. Codexへ編集を依頼する
  5. 変更結果を確認する
  6. HTMLを直接編集する場合

01

ChatGPTアプリを準備する

Windows版ChatGPTデスクトップアプリを用意し、ChatGPTとCodexを同じアプリ内で使える状態にします。

  1. OpenAI公式のWindows版案内を確認し、案内先からChatGPTデスクトップアプリをインストールします。

  2. アプリを起動し、普段使用するChatGPTアカウントでサインインします。

  3. 掲載内容の相談や整理にはChatGPTを使い、コードやローカルファイルを変更するときは、新しいチャット画面のChatGPTドロップダウンなどからCodexへ切り替えます。

デスクトップアプリを使う理由

デスクトップアプリでは、選んだローカルフォルダをCodexの作業対象にできます。Web版だけで相談する場合と異なり、Codexがリポジトリ内のファイルを読み、変更やテストを行えます。

表示は異なる場合があります

製品選択の名称や位置、利用できる機能は、アプリの更新、契約プラン、所属組織の設定、段階的な提供状況によって異なる場合があります。

02

研究室の情報を整理する

Codexへ変更を依頼する前に、掲載する事実と掲載しない情報をChatGPTで整理します。

整理する情報

  • 研究室名
  • 所属
  • 研究テーマ
  • NEWS
  • メンバー
  • プロフィール
  • 論文・研究発表
  • Contact
  • 使用する画像と用途
  • 掲載しない情報

初期カスタマイズ用プロンプトを使う

  1. ChatGPTで、確認済みの研究室情報を整理します。不明な項目は「未定」とし、事実を補わせないようにします。

  2. 後の手順でリポジトリをCodexに開いたら、prompts/INITIAL_CUSTOMIZATION.mdを読むよう依頼します。利用者がファイルを別のアプリで開き、全文をコピーする必要はありません。

  3. ChatGPTで整理した情報をCodexへ貼り付け、入力資料にない事実を追加しないよう伝えます。

推測させない・公開できない情報を入れない

資料にない研究内容、氏名、論文、受賞歴、連絡先などをAIに推測させないでください。個人情報、未公開の研究情報、パスワード、公開許可のない画像は、不用意にChatGPTへ入力したりリポジトリへ保存したりしないでください。

03

Codexでリポジトリを開く

GitHub Desktopでパソコンへcloneしたリポジトリのフォルダを、ChatGPTデスクトップアプリのCodexでプロジェクトとして開きます。

リモートリポジトリ
GitHub上に保存されているホームページのファイルと変更履歴です。
ローカルリポジトリ
GitHub Desktopでcloneして、パソコン上へ保存した作業用フォルダです。
Codexのプロジェクト
Codexが内容を読み、変更や検証を行うことを許可されたローカルフォルダです。

GitHub Desktopで保存場所を確認する

  1. GitHub Desktopを開き、左上の現在のリポジトリ名を確認します。リポジトリ一覧から、テンプレートをもとに作成した自分のリポジトリを選びます。

  2. GitHub DesktopのRepositoryメニューからShow in Explorerを選びます。

  3. エクスプローラーで開いたフォルダの場所を確認します。中にindex.html、prompts、assetsなどがあれば、そのフォルダがCodexで選ぶローカルリポジトリです。

配布元や別のリポジトリを選ばない

academeia/hp_templateではなく、自分用に作成したリポジトリを選びます。複数ある場合は名前をよく確認し、場所が分からなければ編集を始めません。

ChatGPTデスクトップアプリでCodexを開く

  1. ChatGPTデスクトップアプリを起動してサインインし、新しいチャット画面のメニューからCodexを選びます。

  2. 初回画面やプロジェクト選択画面で、Add new project、Add folder、Open folderなど、プロジェクトへフォルダを追加する操作を選びます。WindowsではCtrl+Oでフォルダ選択を開ける場合もあります。

  3. 先ほどGitHub Desktopから確認した、自分のローカルリポジトリのフォルダを選びます。

  4. フォルダへのアクセス確認が表示された場合は、対象の名前と場所が正しいことを確認して許可します。

  5. Codexの画面に、選択したリポジトリ名またはフォルダ名が表示されることを確認します。

操作名はアプリによって異なる場合があります

アプリのバージョンや提供状況により、ボタン名や位置は異なる場合があります。目的は、パソコン上にcloneしたHPtemplateのフォルダを、Codexが作業するプロジェクトとして選ぶことです。

選択するフォルダ

選ぶのは、次の「自分のリポジトリ名」のフォルダです。

Documents
└─ GitHub
   └─ 自分のリポジトリ名  ← このフォルダを選ぶ
      ├─ index.html
      ├─ sample.html
      ├─ prompts
      ├─ assets
      └─ README.md

リポジトリの一部や広すぎるフォルダを選ばない

Documents全体、GitHub全体、promptsだけ、INITIAL_CUSTOMIZATION.mdだけ、無関係な別リポジトリは選びません。

Codexが正しいリポジトリを開いたか確認する

編集を依頼する前に、Codexへ次の確認だけを依頼します。

このプロジェクトがHPtemplateのリポジトリであることを確認してください。
変更は行わず、現在のディレクトリ、branch、HEAD、working tree、
remoteとoriginとの差分、主要ファイルを報告してください。

報告で、対象のリポジトリ名、index.html、prompts/INITIAL_CUSTOMIZATION.md、cleanなworking tree、自分用のGitHubリポジトリを指すremoteを確認します。

結果が違う場合は編集を始めない

remoteが配布元のacademeia/hp_templateを直接指している場合、対象が分からない場合、未コミット変更がある場合は、編集を始めず確認します。既存変更を勝手に破棄、stash、reset、checkout、rebase、commitさせないでください。

フォルダを開いただけではGitHubは変わりません

Codexが開くのはGitHub上のWebページではなく、パソコン上のローカルフォルダです。Codexがファイルを変更しても、CommitしてPushするまではGitHubへ反映されません。Push時にGitHubの認証や許可を求められる場合があります。

04

Codexへ編集を依頼する

整理した情報と作業条件を渡し、変更から検証、Commit、Pushまでを一つの依頼として明確に伝えます。

  1. 初期カスタマイズでは、Codexへprompts/INITIAL_CUSTOMIZATION.mdを読むよう依頼します。Codexがリポジトリ内から読むため、利用者が全文を手作業でコピーする必要はありません。

  2. ChatGPTで整理した確認済みの研究室情報を貼り付け、入力資料にない研究内容、氏名、所属、論文、受賞歴などを推測して追加しないよう伝えます。

  3. 初期カスタマイズ、NEWS追加、メンバー更新など、目的が異なる変更はできるだけ別の依頼に分けます。

  4. CodexへPC幅とスマートフォン幅の表示確認、関連テスト、今回の変更だけのCommit、現在のbranchへのPushまで依頼します。

  5. 作業中に確認や許可を求められた場合は、対象と影響を読んでから回答します。

  6. Codexの作業が終わったら、最終報告が表示されるまで確認します。

研究情報は必ず人が確認

AIが生成・整理した研究内容、氏名、所属、論文、受賞歴、連絡先は、原資料と照合してください。文章が自然でも、事実であるとは限りません。

05

変更結果を確認する

公開前に、Codexの報告、変更ファイル、ブラウザ表示、掲載内容を人が確認します。

  1. Codexの最終報告を読み、実施済み、未実施、テスト結果、未確認事項、残課題を区別します。

  2. 変更ファイルと差分を確認し、依頼していない変更や削除がないか確認します。

  3. ブラウザでサイトを開き、PC幅とスマートフォン幅の両方で文字、画像、リンク、レイアウトを確認します。

  4. 氏名、論文、住所、メールアドレスが正しいことと、人物写真やロゴを含む画像の掲載許可を確認します。

  5. Codexが報告したcommit hashとpush先が、今回のbranchとリポジトリに対応していることを確認します。

  6. 問題があれば同じCodexチャットで、場所、現在の状態、期待する状態を具体的に伝えて修正を依頼します。

GitHub Pagesで公開する

確認済みのサイトを公開する手順は、GitHub Pagesで公開するを参照してください。

補足

HTMLを直接編集する場合

HTMLの手作業編集は、仕組みを理解している人や軽微な修正を行う場合の補足的な方法です。

  • 公開用の編集対象はindex.htmlです。
  • sample.htmlは完成見本なので編集しません。
  • タグやclassは表示や機能に使われるため、不用意に削除しません。
  • 詳しい手作業の説明は、既存のHTMLマニュアルを参照してください。
