GitHub Guide

GitHubで公開・更新する

GitHubを初めて使う人に向けて、テンプレートをパソコンへ用意し、Codexの変更結果を確認して公開するまでを案内します。

GitHub DesktopとCodexの役割

GitHub Desktopは、リポジトリをパソコンへ用意し、変更履歴を確認してGitHubへ送るために使います。サイト内容の作成やHTML、CSS、画像の変更は原則としてCodexへ依頼し、利用者は変更内容と表示結果を確認します。

  1. 準備

01

準備

作業を始める前に、GitHubとGitHub Desktopを使える状態にします。

  1. GitHubでアカウントを用意します。GitHubは、ホームページのファイルと変更履歴をインターネット上で管理するサービスです。

  2. GitHub Desktop公式ダウンロードページから、パソコンに合うアプリをインストールします。

  3. ブラウザのGitHubとGitHub Desktopの両方に、同じGitHubアカウントでログインします。

  4. 公開する文章、画像、連絡先に問題がないか確認します。

注意

作成したホームページはインターネット上へ公開されます。パスワード、個人情報、未公開資料はリポジトリへ入れないでください。

02

テンプレートを手元に用意する

配布用テンプレートから自分のリポジトリを作り、パソコンへコピーします。

リポジトリ
ホームページのファイルと変更履歴を保存する場所です。
clone（クローン）
GitHub上のリポジトリを、自分のパソコンへコピーする操作です。

  1. academeia/hp_templateをブラウザで開きます。

  2. Use this templateを押し、表示されたメニューから新しいリポジトリを作成する項目を選びます。

  3. 所有者を確認し、後から見つけやすいリポジトリ名を入力します。公開してよい内容であることを確認してPublicを選び、作成ボタンを押します。

  4. 作成した自分のリポジトリをGitHub Desktopでcloneします。GitHub Desktopのclone画面で対象を選び、パソコン上の保存先を指定してCloneを押します。

  5. cloneが完了したら、GitHub Desktopに表示されたリポジトリ名とパソコン上の保存場所を確認します。

Use this templateが表示されない場合

配布元リポジトリの設定が完了していない可能性があります。無理に別の操作をせず、配布元へ確認してください。

公開するファイルに注意

Publicを選んだリポジトリの内容は誰でも確認できます。パスワード、個人情報、未公開資料を入れないでください。

03

GitHub Desktopで変更を反映する

Codexがパソコン上で変更した内容を確認し、必要に応じてGitHub Desktopでも状態を確認します。

Commit（コミット）
選んだ変更内容を、一つの記録としてパソコン上に保存することです。
Push（プッシュ）
パソコン上のCommitをGitHubへ送ることです。

  1. GitHub Desktopのリポジトリ一覧から、編集する自分のリポジトリを選びます。

  2. メニューのShow in Explorerなど、保存フォルダを開く項目を選びます。表示名はOSによって異なる場合があります。

    Codexで選ぶフォルダと確認方法は、Codexでリポジトリを開くを参照してください。

  3. サイト内容の作成やHTML、CSS、画像の変更は、原則としてCodexへ依頼します。毎回利用者がHTMLを直接編集する必要はありません。

  4. Codexの作業後、GitHub DesktopのChangesで変更されたファイルと内容を確認できます。

  5. 利用者がGitHub DesktopからCommitする場合は、Summaryへ「研究テーマを更新」のような短い説明を入力します。

  6. 利用者が操作する場合は、変更内容を確認してCommit to mainを押します。別のbranchを選んでいる場合は、ボタンにそのbranch名が表示されます。

  7. 利用者が操作する場合は、Commit後に表示されるPush originを押し、変更をGitHubへ送ります。

最後にPushまで行います

CommitしただけではGitHub上の内容は更新されません。必ずPush originまで行ってください。

CodexがCommitとPushを行った場合

Codexへテスト、Commit、Pushまで依頼した場合は、最終報告にあるテスト結果、commit hash、push先を確認します。GitHub Desktopの手順は、変更状態を理解したいときや手動操作が必要なときに利用してください。

04

GitHub Pagesで公開する

GitHub Pagesは、リポジトリ内のHTMLをホームページとして公開する機能です。

  1. ブラウザで、テンプレートから作成した自分のリポジトリを開きます。

  2. リポジトリのSettingsを開きます。見当たらない場合は、リポジトリ上部の追加メニューも確認します。

  3. Settings内のPagesを開きます。

  4. Build and deploymentのSourceで、Deploy from a branchを選びます。

  5. 公開元のbranchにmain、フォルダに/(root)を選び、Saveを押します。

  6. 設定の保存後、公開処理が完了するまで待ちます。初回は表示まで数分かかる場合があります。

  7. Pagesに表示された公開URLを開き、文字や画像が正しく表示されるか確認します。

公開範囲を確認

GitHub Pagesのサイトはインターネット上から見えます。公開URLを開き、意図しない文章、画像、個人情報が含まれていないか確認してください。

05

更新する

公開後も同じリポジトリをCodexで開き、編集、確認、Commit、Pushの流れを繰り返します。

  1. パソコン上にcloneした同じリポジトリをCodexで開きます。

  2. 変更したい内容をCodexへ具体的に伝え、入力資料にない事実を追加しないよう依頼します。

  3. Codexの最終報告と変更ファイルを確認し、パソコンのブラウザでも表示を確認します。

  4. テストが成功したことを確認し、Codexが報告したcommit hashとpush先を確認します。

  5. 必要に応じてGitHub DesktopのChangesや履歴を開き、変更がCommit・Pushされていることを確認します。

  6. 公開ページを再読み込みし、更新が反映されたことを確認します。

表示が変わらない場合

Pushを忘れていないか確認し、ブラウザを再読み込みします。公開ページへの反映まで少し待つ場合もあります。

リポジトリを作り直さない

更新のたびに新しいリポジトリを作る必要はありません。最初に作った同じリポジトリ内のファイルを編集します。
