# Codex Project Workflow Skill

## 基本方針

- 既存仕様を勝手に大きく変えない。
- まず現在の実装を読んでから変更する。
- 小さく安全に変更し、動作確認しやすい単位で進める。
- UI変更、データ保存、外部API利用、課金・認証まわりは勝手に拡張しない。
- ユーザーが「シンプルに」と言っている場合、多機能化より保守性を優先する。

## 作業順

1. 関連ファイルを読む。
2. 既存の設計意図を推定する。
3. 変更方針を短くまとめる。
4. 最小差分で実装する。
5. 実行・テスト・lint可能なら確認する。
6. 変更点と未確認点を明示する。

## 禁止

- 仕様にないユーザー登録、DB、履歴保存、クラウド保存、AI API利用を追加しない。
- 既存UIを大幅に作り替えない。
- セキュリティ上危ない暫定実装を「あとで直す」前提で入れない。
- 表示・保存・認証・課金などの責務を曖昧に混ぜない。

## 出力方針

- 変更したファイルを明示する。
- 動作確認したコマンドを明示する。
- 未確認の点は未確認として書く。
- 追加した仕様と既存仕様の差分を短く説明する。
